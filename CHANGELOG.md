# Changelog

All notable changes to Factonio are documented in this file.
Every user-facing pull request adds an entry under `## Unreleased`.

## Unreleased

- Opt-in high-rigor multi-vendor verification panel (Wave 3 Unit 3): `config.py` adds `RIGOR_LEVELS = ("standard", "high")`, `default_rigor` (default `standard`) and `verify_panel` settings, `resolve_rigor`, and `resolve_verify_panel` / `validate_verify_panel` (precedence: `panel_models` override -> `repos.<slug>.models.verify_panel` -> `auxiliary.factonio_verify_panel` -> `settings.verify_panel`), which infer each member's vendor family through routers (`openrouter/`, `vertex/`, `bedrock/`) and require >= 2 members across >= 2 distinct known vendors. Per-repo `default_rigor` (`standard` | `high` | `inherit`) is editable via `update_repo`, `factonio_update_repo`, `hermes factonio update --default-rigor`, and `PATCH /repos/{slug}`, and surfaced additively in `GET /repos`, `GET /models` (`verify_panel`, `default_rigor`), `hermes factonio models` and `hermes factonio doctor` (which warns when `high` rigor has no valid panel). `spawn_verification_pair` / `factonio_spawn_verify` accept `rigor` and `panel_models`: `standard` keeps the exact two-card behavior (plus `rigor` / `panel: null`), while `high` fails closed on an invalid panel or fans out one barrier-preserving Diff + Black-Box pair per panel model (repo harness on every Black-Box lane) under a shared `panel_id`, logged to `trail.db`. New fail-closed `aggregate_panel_verdicts` / `evaluate_verification_panel` (any reject -> `reject`, any inconclusive -> `inconclusive`, unfinished -> `pending`, unanimous multi-vendor pass -> `pass`, degenerate single-vendor -> `inconclusive`) with `disagreement_summary` and aggregated findings, exposed via the `factonio_evaluate_panel` tool and `hermes factonio panel`, recording `verify_panel_consensus` in `trail.db`. Additive `panel_id` / `panel_vendor` on `/cards`, `panels` in `factonio_status`, and `verification_panels` in `/metrics`. Skills, README, docs and `THIRD_PARTY_NOTICES.md` (pstack multi-model review panel) updated.
- Repo-local verification harness (Wave 3 Unit 1): new stdlib-only `harness.py` detects a repo's stack, entrypoints, CI commands, HTTP routes and CLI commands and bootstraps a git-tracked `.factonio/verify.md` (`Launch` / `Doctor` / `Drive` / `Evidence` / `Cleanup` + `Feature Map` + `Hooks`) and `.factonio/harness.json` (`schema_version: 1`), refusing to overwrite without `force` and supporting `dry_run`; `check` validates sections, schema (type-safely: malformed field types become structured errors, never exceptions), hooks and dead globs and returns `ok` plus an equal `valid` boolean (optionally running Doctor commands and `visual_diff` / `invariant` / `custom` hooks, where only required-hook failures fail; each Doctor command / hook runs in its own process session and a timeout SIGKILLs and reaps the whole process group so shell descendants cannot write after `timed_out: true` is returned); bootstrapped feature IDs are unique (`root`, then `-2` / `-3` suffixes for colliding slugs); `audit` is strictly read-only (`--no-optional-locks`) and reports `uncovered_changed_files`, `stale_features`, `orphaned_globs`, new/removed routes and CLI commands with `severity: clean | stale | missing`. Exposed via the `factonio_bootstrap_verify` tool, `hermes factonio harness {init|check|show|audit} <repo>`, and a `harness-audit` automation blueprint; `factonio_spawn_verify` injects a discovered harness into Black-Box cards only (additive `harness_present` / `harness_path`), and `factonio:verify-blackbox` may read `.factonio/` while `git diff` and source stay forbidden. Credits pstack's `create-verification-skill` / `maintain-verification-skill` in `THIRD_PARTY_NOTICES.md`.
- Stacked PR landing: `spawn_implementation_card` / `factonio_spawn_implement` accept `base_branch` and `stack_parent_pr`, pre-seed a local `<project>/stack-<id>` branch at the parent tip (via `seed_stacked_branch`) so the worker's worktree starts on the parent, and instruct `gh pr create --base <base_branch>`. `inspect_pr_gate` / `merge_pr` now report additive `default_branch` and `is_stacked` (plus `merge_pr(delete_branch=...)`, local sync of the PR's true base, and `assess_trunk_drift(base_branch=...)`). New `inspect_pr_patch_id`, `restack_pr` and `restack_stack` rebase a child PR onto its new base inside a throwaway linked worktree (`git rebase --onto <remote>/<new_base> <old_base>`, so squash-merged and deleted parents restack cleanly without touching the main checkout), push with `--force-with-lease`, retarget with `gh pr edit --base`, compare `git patch-id --stable` before/after to report `verdict_continuous` / `reverify_required`, abort cleanly on conflicts, and log `restack_pr` to `trail.db`. Exposed as the `factonio_restack_pr` tool and `hermes factonio restack`.
- Desktop Decision Trail UI: `/factonio` gains a **Decision Trail** section (`GET /trail`) with repository/workstream/phase filters, structured evidence pills (PR link, short SHA, card, patch-id, test counts, idle/pid), result tone badges, navigable superseded ↔ superseding lineage (targets outside the loaded 200-row window or a `?tenant=` deep-link scope are fetched on demand from the new additive `GET /trail/{decision_id}` route, pinned into the ledger, and scrolled to, focused and flashed), a hide-superseded toggle, and populated/filtered/empty/loading/error states; the docked sidebar tab shows per-workstream decision counts with an expandable decision list (and an "Open in Decision Trail" deep link) plus per-card decisions in the card drawer, sharing one visibility-aware `/trail?limit=200` poll. README dashboard, sidebar and workflow media were regenerated with realistic trail fixtures.
- Worktree pruning now protects ignored non-regenerable local data (`.env`, local databases, data dirs) as `hold-wip` while treating untracked-only and regenerable-cache worktrees as `scratch:N`/`safe` (reporting `dropped_scratch`); watchdog alert deduplication is now kind- and run-aware so `stale_running` -> `dead_worker`/`runtime_exceeded`/`triage_needs_input` escalations alert immediately, and fresh edits inside new untracked directories count as workspace side effects.
- Watchdog liveness and worktree hygiene: the dispatch-tick watchdog now flags dead `worker_pid`s (`dead_worker`) and exceeded `max_runtime_seconds` (`runtime_exceeded`) immediately, uses phase-aware stale thresholds (`resolve_stale_heartbeat_minutes`), detects heartbeating workers with no side effects (`no_side_effects`), and optionally triages ambiguous stalls with an explicitly configured `factonio_watchdog` model under a per-task cooldown and 15s timeout with deterministic fallback. New `hermes factonio worktrees [repo] [--base <ref>] [--prune-safe] [--json]` audits git worktrees into `hold-wip` / `hold-active-card` / `hold-open-pr` / `safe` / `review` buckets and removes only `safe` ones on request; the audit is strictly read-only (`--no-optional-locks`) and pruning re-verifies HEAD, local work and active-card ownership (failing closed when a required `kanban.db` is unreadable, missing or vanished) with the same classifier as the audit, holds locked worktrees as `review`, never classifies a worktree as `safe` when it contains another registered worktree or nested repository (`review`) or an active card's workspace (`hold-active-card`, by resolved-path containment), and never uses `rmtree` to override a `git worktree remove` refusal.
- Added the append-only SQLite decision trail `trail.db` (`trail.py`: WAL with concurrency-safe cold-start initialization and bounded lock-contention retry, `schema_meta` v1, no-update/no-delete triggers, validated `supersedes_id` corrections) with automatic logging of workstream start, escapes, design/implement/verify spawns, and PR gate/merge outcomes; the `factonio_log_decision` tool; `hermes factonio trail`; `GET /api/plugins/factonio/trail`; and an additive `trail` block in `/metrics`. The retro blueprint now runs a `/correct` retrospective over Kanban metrics and `trail.db`, `escaped_from` workstreams require a Verification Gap Analysis explaining why both Diff Check and Black-Box Check missed the bug, the orchestrator skill gains `ketchup` handoff rules, `check_cross_model_warning` flags same-vendor/model-family Verification (including via routers like `openrouter` and `vertex`), and README/`THIRD_PARTY_NOTICES.md` credit the Wave 2 pstack patterns.
- Hardened the PR gate and merge flow: `factonio_pr_gate` now uses paginated `gh api graphql` (>100 checks, review threads, `reviewDecision`, head rollup state) with 4-tier blocker classification (`blocker_tier`, `unresolved_threads`); `factonio_merge_pr` confirms the live merge state (`merged` vs. `queued`) and safely fast-forwards the local default branch; added `git patch-id` continuity and trunk-drift helpers; and verification metrics/cards support tri-state `inconclusive` verdicts.
- Upgraded the worker execution contract (`WORKER_SOUL_MD`) and all five phase skills with pstack-derived rigor: Architect step, empirical prototypes, Throughput Checkpoint and binary-search bug diagnosis (`define`); Attack the Premise, skeptical review-thread triage with prompt-injection hygiene, comment hygiene and a `<=40-line` PR briefing (`implement`); run-proven findings, blast-radius proof and base-vs-PR attribution (`verify-diff`); tri-state `pass`/`reject`/`inconclusive` verdicts (`verify-blackbox`); and the 4-tier PR gate, live merge readback, fresh-worker fix rounds and `git patch-id` verdict continuity (`orchestrator`). Credited Lauren Tan (@poteto) and pstack in `README.md` and added `THIRD_PARTY_NOTICES.md` with pstack's MIT notice.
- Added Concept A ("Machined Winged Cogwheel") Factorio × Hermes brand assets under `docs/images/` (dark/light README banners, dark/light/monochrome logo variants, PNG exports, and 1280×640 2:1 social/marketplace cover), wired the light/dark `<picture>` hero banner into `README.md`, and extended `tools/check_repo_integrity.py` to verify HTML `srcset` paths.
- Moved canonical repository to `omnim-ai/factonio` and updated `plugin.yaml` metadata (`homepage`, `tags`).
- Added GitHub Actions CI pipeline (lint, manifest/link integrity, full 90-test suite against pinned Hermes Agent, and changelog gate) plus daily upstream Hermes compatibility checks and Dependabot config.
- Added open-source contributor documentation: `CONTRIBUTING.md`, `SECURITY.md`, `AGENTS.md`, `docs/development.md`, `docs/architecture.md`, PR/issue templates, and visual `README.md` with Desktop UI screenshots, architecture diagram, and animated feature demos.
- Added project-local contributor skill `.agents/skills/update-readme-media/SKILL.md`, upgraded `tools/capture_readme_media.py` (`--check-deps`, `--only`, `--qa-dir`, cross-platform browser discovery, image header validation), and added the mechanical `README media freshness` CI check (with `no-visual-change` label override) and review checklist.
- Added reproducible media capture harness (`tools/capture_readme_media.py`) and static integrity checker (`tools/check_repo_integrity.py`).

## 0.1.0

- Initial pure-Hermes, phase-based software factory plugin (`factonio`).
- Dedicated headless `factonio` worker profile setup and readiness diagnostics (`hermes factonio init`, `hermes factonio doctor`).
- Four-phase orchestration across Definition (`factonio:define`), optional Phase 1b UI/UX Design (`factonio:design` with Claude Design `/design` and pure-Hermes fallback), parallel git-worktree Implementation (`factonio:implement`), and mutually isolated parallel Verification (`factonio:verify-diff` + `factonio:verify-blackbox` separated by a `holdout/` information barrier).
- Exact-HEAD PR verification gate and squash-merge tooling (`factonio_pr_gate`, `factonio_merge_pr`), plus per-repo configuration updates via CLI (`hermes factonio update`), agent tool (`factonio_update_repo`), and Dashboard API (`PATCH /api/plugins/factonio/repos/{slug}`).
- Five native Hermes Auxiliary Model slots (`factonio_define`, `factonio_design`, `factonio_implement`, `factonio_verify`, `factonio_watchdog`) with cross-model independence warnings.
- In-process Kanban dispatch-tick watchdog, SQLite phase metrics and escape-rate tracking, and Factonio Phase Retro automation blueprint.
- Zero-build Hermes Desktop UI (`desktop/plugin.js`): `/factonio` metrics dashboard with inline editable Registered Repositories table, hideable right-sidebar Factonio tab docked beside Files (with workstream pipeline bars, scope/status/phase filters, and expandable card drawers), Settings landing page with Auxiliary Models deep-links, status bar pill, and `::your-turn` transcript directive.
